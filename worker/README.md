# PF Store · синхронизация заказов

Этот воркер добавляет сайту то, чего не может дать GitHub Pages:
общую базу заказов и статусы, которые менеджер меняет со своего Telegram.

## Зачем

Сайт на GitHub Pages — это только файлы. Он не может сам узнать,
отправил ли покупатель сообщение и на каком этапе заказ.
Сейчас история заказов хранится в браузере (`localStorage`) и честно
показывает этапы: создан → у менеджера → доставка → получен.

Воркер делает следующий шаг:

- заказы сохраняются в Cloudflare KV;
- покупатель видит свои заказы на любом устройстве;
- менеджер видит все заказы и переводит их по четырём этапам;
- подпись Telegram `initData` проверяется на сервере;
- при желании приходит уведомление в Telegram.

Всё в бесплатном тарифе Cloudflare Workers.

## Бот и webhook

Webhook: `POST /telegram`, адрес `https://pf-store-orders.vegnette.workers.dev/telegram`.
Telegram присылает его только с заголовком `x-telegram-bot-api-secret-token`,
значение которого совпадает с секретом `TG_WEBHOOK_SECRET`.

Команды бота:

- `/start` — приветствие и кнопка «Открыть магазин»;
- `/catalog` — где смотреть актуальные цены;
- `/orders` — где посмотреть свои заказы и статусы;
- `/help` — помощь и контакт менеджера.

У бота также заданы описание, короткое описание и кнопка меню типа `web_app`
на `https://vegnette.github.io/pf-store/`.

Подпись `initData` проверяется токеном любого из двух ботов
(`BOT_TOKEN_MAIN` или `BOT_TOKEN`), поэтому мини-приложение работает и из
основного бота, и из старого админ-бота.


## Наличие и подписки

- `GET /stock` — публичный список ручных изменений наличия: `{"stock":{"2":3}}`.
- `POST /` `{ type:'stock', productId, stock, title, price, initData }` — менеджер
  меняет наличие. Если `stock > 0`, всем подписчикам уходит сообщение.
- `POST /` `{ type:'watch', productId, initData }` — покупатель подписывается
  на поступление. `canNotify:false` значит, что бот не смог написать:
  человек не нажал `/start` у основного бота.

Подписки хранятся в KV с префиксом `watch:<товар>:<id>`, изменения наличия —
`stock:<товар>`. Подписка удаляется после успешного уведомления.

## Ежедневный отчёт

Cron `0 14 * * *` (14:00 UTC = 21:00 Барнаул) собирает заказы за барнаульские
сутки и шлёт в `MANAGER_CHAT_ID`: число заказов, выручку, средний чек,
топ-товар и сколько заказов ждут подтверждения.

Ручной запуск (нужен секрет `REPORT_KEY`):

```bash
curl -X POST https://pf-store-orders.vegnette.workers.dev/run-report \
  -H "X-Report-Key: ВАШ_КЛЮЧ"
```

## Плашка «Открыть в Telegram»

В обычном браузере внизу появляется плашка с кнопкой на основного бота.
Она скрывается в мини-приложении Telegram и после нажатия «✕» (запоминается
в `localStorage`).


## Шаг 1. Бот

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Сохраните токен вида `123456789:AA...`.
3. Узнайте свой числовой Telegram ID, например через [@userinfobot](https://t.me/userinfobot).
4. Настройте мини-приложение:
   - `/newapp` (или `/setmenubutton`) → выберите бота → укажите URL сайта.

Без Mini App Telegram не передаёт имя и аватар — сайт покажет «Откройте через Telegram».

## Шаг 2. Cloudflare

```bash
cd worker
npm install -g wrangler
wrangler login
wrangler kv namespace create ORDERS_KV
```

Скопируйте `id` из ответа в `wrangler.toml`.
В `MANAGER_IDS` укажите свой числовой ID (несколько — через запятую).

```bash
wrangler secret put BOT_TOKEN
wrangler secret put BOT_TOKEN_MAIN   # токен основного бота @PF_Store22_bot
wrangler secret put MANAGER_CHAT_ID   # необязательно
wrangler secret put REPORT_KEY        # ручной запуск отчёта
wrangler secret put TG_WEBHOOK_SECRET # защита webhook
wrangler deploy
```

Получите адрес вида:

```
https://pf-store-orders.ВАШ_АККАУНТ.workers.dev
```

Важно: перед первым заказом менеджер должен хотя бы раз открыть бота
и нажать `/start`. Иначе Telegram запрещает боту писать первым,
и уведомление не дойдёт (в логах `wrangler tail` будет `telegram_notify_failed`).

## Шаг 3. Сайт

В `script.js` заполните:

```js
const ORDERS_ENDPOINT = 'https://pf-store-orders.ВАШ_АККАУНТ.workers.dev';
const MANAGER_USERNAMES = ['pf_store_manager'];
const MANAGER_IDS = [ВАШ_ЧИСЛОВОЙ_ID];
const TELEGRAM_BOT_USERNAME = 'имя_вашего_бота';
```

Задеплойте сайт заново. Готово:

- `GET  /?initData=...` — список заказов (свои или все для менеджера);
- `POST /` `{ type: 'order', order, initData }` — создать/обновить заказ;
- `POST /` `{ type: 'status', id, status, initData }` — статус (только менеджер);
- `POST /` `{ type: 'delete', id, initData }` — удалить тестовый заказ (только менеджер).

Статусы: `created` (создан), `manager` (у менеджера), `delivery` (в доставке),
`received` (получен), `canceled` (отменён). Старые значения `awaiting`, `sent`
и `delivered` автоматически приводятся к новым.

Заказы с `test: true` или id, начинающимся с `TEST`, не попадают в историю
покупателя, ежедневный отчёт и уведомления. Менеджер видит их с пометкой
и может удалить.

## Важно про безопасность

- `BOT_TOKEN` хранится только в секретах Cloudflare, не в репозитории.
- Подпись `initData` проверяется HMAC-SHA256 по алгоритму Telegram.
- Покупатель может менять только свой заказ и только подтвердить отправку.
- Статусы «создан / у менеджера / в доставке / получен / отменён» меняет
  только менеджер — по числовому ID из `MANAGER_IDS`.
- Цены и суммы приходят с клиента: перед оплатой менеджер всё равно
  сверяет заказ вручную.

## Ограничения бесплатного тарифа

- KV: около 100 000 чтений и 1 000 записей в сутки — для магазина с запасом.
- Список заказов читается целиком. При тысячах заказов стоит перейти
  на D1 или хранить заказы по месяцам.

## Что теперь уходит в воркер

Вместе с заказом сохраняются:

- имя и телефон покупателя (`order.customer`);
- способ получения, адрес и комментарий (`order.delivery`);
- состав заказа, скидки и итоговая сумма.

Поэтому уведомление менеджеру в Telegram сразу содержит контакт и адрес.
Если `ORDERS_ENDPOINT` пуст, эти же данные попадают в текст сообщения,
которое сайт открывает в чате с менеджером.

## PWA и поисковики

- `manifest.webmanifest`, `sw.js` и иконки в `images/` включают установку
  сайта на главный экран и офлайн-оболочку.
- `robots.txt` и `sitemap.xml` лежат в корне. Они уже настроены на
  `https://vegnette.github.io/pf-store/`; при смене домена обновите адреса
  и в этих файлах, и в `canonical`/`og:url` в `index.html`.
- Мета-теги товара и JSON-LD подставляются при открытии карточки.
  Социальные сети читают только статический HTML, поэтому для красивых
  превью каждой ссылки нужен серверный рендеринг или отдельные страницы.

## Если воркер пока не нужен

Оставьте `ORDERS_ENDPOINT = ''`. Сайт продолжит работать:
история и статусы будут локальными, а в профиле будет честная пометка
«локально».

## Проверка без Telegram

Панель менеджера можно включить в обычном браузере, добавив к адресу:

```
https://ваш-сайт/?manager=1
```

Это удобно для проверки статусов и вёрстки. Но имя и аватар в обычном
браузере не появятся: Telegram передаёт их только внутри мини-приложения.
