# ТЗ: бесплатные доработки под конверсию

Статус: **только спецификация, код не написан**. Реализуем по одному пункту после подтверждения.

Реализовано (коммит «Improve trust strip, live status, cart reminder, search empty state»):
пункты **4** (брошенная корзина), **5** (полоса гарантий), **6** (живой статус),
**8** (Open Graph + «Поделиться») и **10** (поиск без тупика).
Везде добавлено уточнение: заказать можно в любое время, менеджер принимает заказ в работу с 10:00.

Стек не меняется: GitHub Pages (статика), Cloudflare Worker `pf-store-orders`, KV `ORDERS_KV`, Telegram Bot API `@PF_Store22_bot`.
Платных сервисов, аналитики и внешних SDK нет.

Общие правила для всех пунктов:

- не ломать существующие анимации `cardIn`, `badgePop`, `heartPop`, `toastIn`, `tgBannerIn`, sheen и spotlight;
- уважать `prefers-reduced-motion` (все новые движения отключаются);
- мобильный первым: проверка на 375×667 и 390×844;
- не отправлять заказ автоматически — подтверждение в Telegram остаётся обязательным;
- каждый пункт = отдельный коммит + поднятая версия кеша в `sw.js` (`pf-store-v10`, `v11`, …).

## 1. Sticky-панель «Заказать» на карточке товара

**Зачем:** кнопка покупки уезжает вверх, пока листают фото. Панель держит действие в поле зрения.

**Где:** `index.html` (модалка `#productModal`), `style.css`, `script.js` (`openProduct`).

**Что сделать**

1. Внутри `.modal-content` карточки товара добавить блок:
   ```html
   <div class="product-buybar" id="productBuybar" hidden>
     <div class="product-buybar-price">
       <span class="product-buybar-value" id="buybarPrice">1 500 ₽</span>
       <span class="product-buybar-old" id="buybarOld"></span>
     </div>
     <button type="button" class="product-buybar-btn" id="buybarAdd">В КОРЗИНУ</button>
   </div>
   ```
2. Панель — `position: sticky; bottom: 0` внутри скроллящегося контейнера модалки, с фоном `var(--surface)`, верхней границей и `backdrop-filter: blur(12px)`, `padding-bottom: env(safe-area-inset-bottom)`.
3. `openProduct(id)` заполняет цену/старую цену; если `stock === 0` — кнопка меняется на «СООБЩИТЬ О ПОСТУПЛЕНИИ» (существующая подписка).
4. Клик по кнопке вызывает тот же `addToCart(id)`, что и основная кнопка, с существующими `playSound('tap')` и `triggerHaptic('success')`.
5. Панель скрывается, когда основная кнопка «В корзину» видна (IntersectionObserver на основной кнопке, `threshold: 0.9`) — чтобы не дублировать действие.

**Края:** модалка с длинным описанием и отзывами; товар без фото; `stock = 0`.

**Приёмка:** на телефоне при прокрутке фото кнопка всегда доступна; после добавления в корзину тост появляется, как раньше; на десктопе панель не перекрывает контент.

**Оценка:** 2–3 часа.

## 2. Заказ в один тап («Как в прошлый раз»)

**Зачем:** форма — самый дорогой шаг. Данные уже сохраняются в `pf_customer`, но их всё равно надо подтверждать руками.

**Где:** `script.js` (`prefillCheckoutForm`, `openCheckout`), `index.html` (модалка оформления).

**Что сделать**

1. В `#checkoutModal` над формой добавить компактный блок быстрого заказа:
   ```html
   <button type="button" class="checkout-quick" id="checkoutQuick" hidden>
     <span class="checkout-quick-title">Оформить как в прошлый раз</span>
     <span class="checkout-quick-sub" id="checkoutQuickSub"></span>
   </button>
   ```
2. Показывать, если в `pf_customer` есть имя и телефон (минимум 10 цифр) **и** пользователь уже делал заказ (в `pf_orders` есть запись). Подпись: «Иван · +7 961 …· самовывоз».
3. Клик: подставляет значения в поля, ставит выбранный способ получения, проигрывает `playSound('tap')`, скроллит к кнопке «ПЕРЕЙТИ В TELEGRAM» и подсвечивает её (одноразовый `box-shadow`, 900 мс).
4. Никакой отправки без нажатия основной кнопки.
5. Телефон в подписи маскировать: `+7 961 ··· -44`.

**Края:** сохранён адрес устарел; пользователь сменил город — поля остаются редактируемыми; нет `pf_customer` — блок скрыт.

**Приёмка:** повторный заказ = 2 нажатия; первый заказ не показывает блок; данные не подставляются в обход проверок.

**Оценка:** 2 часа.

## 3. «Заказать снова» в истории заказов

**Зачем:** повторная покупка — самый дешёвый заказ.

**Где:** `script.js` (`renderOrders`, `renderOrderCard`), `style.css`.

**Что сделать**

1. В карточке заказа в статусе `received` или `canceled` добавить кнопку «ЗАКАЗАТЬ СНОВА».
2. По клику: для каждого товара заказа проверить `products` по `id`; если товар есть и `stock > 0` — добавить в корзину с сохранением количества (не больше остатка), затем `openCheckout()`.
3. Если часть товаров недоступна — показать `showToast('2 товара больше нет в наличии — добавили остальные')` и открыть корзину, а не чекаут.
4. Если недоступно всё — тост «Этих товаров сейчас нет» + кнопка «Написать менеджеру».
5. Не дублировать товары: если позиция уже в корзине, увеличить `qty` в пределах `stock`.

**Края:** заказ из другого города; товар подорожал — цена берётся текущая, старая не подставляется; тестовые заказы кнопку не показывают.

**Приёмка:** повторное добавление не создаёт дублей; сумма пересчитывается; статусы и история не меняются.

**Оценка:** 2–3 часа.

## 4. Брошенная корзина

**Зачем:** человек ушёл на этапе оформления — самый тёплый трафик.

**Где:** `script.js` (`checkout`, `openModal`), `index.html` (главная).

**Что сделать**

1. При открытии оформления сохранять снимок: `pf_cart_snapshot = { ids: [...], qty: n, at: ISO }`.
2. При следующем визите (не раньше чем через 30 минут и не позже 7 дней, корзина не пуста) показать на главной баннер под шапкой:
   «Вы остановились на Apple Watch S11 46mm — осталось 1 шт.» + кнопки «Вернуться к заказу» и «✕».
3. Баннер — `role="status"`, не перекрывает поиск, анимация `toastIn`, скрытие запоминается в `pf_cart_nudge_dismissed` (timestamp, 3 дня).
4. «Вернуться к заказу» → `openCheckout()`.
5. Если товара уже нет в наличии — текст «Товар закончился, но есть похожие» и кнопка на каталог.

**Края:** очищенная корзина; заказ уже оформлен — снимок удалять в `checkout()` после успешной отправки; тестовые заказы не создают снимок.

**Приёмка:** баннер появляется один раз, не мешает навигации, кнопка ведёт в чекаут; после заказа не возвращается.

**Оценка:** 3 часа.

## 5. Полоса гарантий вместо юридического блока

**Зачем:** снимает страх «переведу деньги и пропадут». Юридические страницы убраны, доверие нужно показать коротко.

**Где:** `index.html` (блок `.trust-strip` на главной), `style.css`.

**Что сделать**

1. Заменить/дополнить существующую полосу четырьмя пунктами с иконками:
   - «Проверка при получении»;
   - «Возврат 24 часа» (если правило другое — взять фактическое);
   - «Отправка по всей России»;
   - «Отвечаем 10:00–21:00».
2. Каждый пункт — 2 строки: заголовок 10 px uppercase + подпись 9 px `--text-3`.
3. На мобиле — сетка 2×2, на десктопе — 4 в ряд.
4. Никаких обещаний, которых магазин не выполняет: тексты согласовать.

**Приёмка:** блок читается без скролла на 375 px; не конфликтует с `reveal`-анимацией.

**Оценка:** 1 час.

## 6. Живой статус магазина

**Зачем:** «сейчас закрыто» без объяснения = потеря. Нужно говорить, когда ответят.

**Где:** `script.js` (`updateStoreStatus`), `index.html` (шапка/чекаут).

**Что сделать**

1. Расширить `updateStoreStatus()`: открыто (10:00–21:00 Барнаул, UTC+7) → «ОТКРЫТО · ОТВЕТИМ ЗА 10 МИНУТ»; закрыто → «ЗАКРЫТО · ОТКРОЕМСЯ В 10:00».
2. В оформлении при закрытии — уже существующая подсказка `checkoutClosedHint`, дополнить: «Заказ можно оставить — ответим после 10:00».
3. Пересчёт раз в минуту через `setInterval` (очищать при `visibilitychange` → `hidden`, чтобы не жрать батарею).
4. Учитывать `Intl.DateTimeFormat` с `timeZone: 'Asia/Barnaul'`, а не смещение вручную.

**Края:** переход через полночь; устройство с неверными часами — использовать `Date.now()` и таймзону, не локальный час.

**Приёмка:** текст меняется в 10:00 и 21:00 по Барнаулу; при скрытой вкладке таймер не крутится.

**Оценка:** 2 часа.

## 7. Блок «Уже забрали» (реальные отзывы)

**Зачем:** соцдоказательство. Самый дешёвый рост доверия без оплаты рекламы.

**Где:** новый файл `reviews.json`, `index.html` (секция на главной), `script.js` (`loadReviews` уже рисует отзывы в «О нас»).

**Что сделать**

1. `reviews.json`: `[{ "name": "Иван", "city": "Барнаул", "text": "…", "rating": 5, "product": "AirPods 4", "photo": "./images/reviews/1.jpg", "date": "2026-11-01" }]`.
2. На главной — горизонтальная лента из 5–8 карточек под каталогом «Новые поступления»: фото (если есть), текст 2–3 строки, имя + город, звёзды.
3. Загрузка через `fetch('reviews.json')` с фолбэком: если файла нет — секция скрыта (никаких пустых блоков).
4. Фото — только реальные, с согласия покупателя. Никаких стоков.
5. Лента: `scroll-snap-type: x mandatory`, без автопрокрутки.

**Приёмка:** пустой/битый JSON не ломает страницу; лента листается пальцем; высота карточек не прыгает при загрузке.

**Оценка:** 2 часа (без сбора контента).

## 8. Превью ссылки в Telegram (Open Graph)

**Зачем:** пересланная ссылка без превью = половина кликов.

**Где:** `index.html` `<head>`.

**Что сделать**

1. Добавить:
   ```html
   <meta property="og:type" content="website">
   <meta property="og:site_name" content="PF Store">
   <meta property="og:title" content="PF Store — электроника с проверкой перед покупкой">
   <meta property="og:description" content="Гарантия 14 дней · доставка по всей России · заказ через Telegram">
   <meta property="og:image" content="https://vegnette.github.io/pf-store/images/og-cover.jpg">
   <meta property="og:url" content="https://vegnette.github.io/pf-store/">
   <meta name="twitter:card" content="summary_large_image">
   ```
2. Подготовить `images/og-cover.jpg` 1200×630: логотип, «PF STORE», «Барнаул · доставка по РФ», без мелкого текста.
3. Кнопка «Поделиться» в карточке товара: `https://t.me/share/url?url=…&text=…` с названием и ценой.
4. Проверить превью через `@WebpageBot` после деплоя (кэш Telegram).

**Края:** GitHub Pages отдаёт статику — превью обновится после переобхода ботом.

**Приёмка:** в чате Telegram видно картинку, заголовок и описание; ссылка на товар — с ценой в тексте.

**Оценка:** 1–2 часа.

## 9. Deep link в бота с товаром

**Зачем:** из карточки сразу в диалог с готовым контекстом, без поиска вручную.

**Где:** `script.js` (карточка товара), `worker/index.js` (webhook `/start`).

**Что сделать**

1. Кнопка «Спросить в Telegram» в карточке: `https://t.me/PF_Store22_bot?start=item_<id>`.
2. В Worker при `/start item_5`: найти товар (передать название в параметре небезопасно — брать из `products.json` на сборке нельзя, поэтому текст зашиваем в `start` как `item_5` и в Worker держать минимальный справочник `id → название+цена` либо просто отвечать «Вы смотрите товар #5, напишите, что интересует»).
3. Ответ покупателю: карточка товара текстом + кнопки «Оформить», «Наличие», «Назад в магазин».
4. «Оформить» → менеджеру приходит уведомление с товаром и `user.id`.

**Края:** неизвестный `id`; старый клиент без `start` — обычное приветствие.

**Приёмка:** переход по ссылке открывает бота с сообщением по товару; менеджер видит, откуда пришёл человек.

**Оценка:** 3–4 часа.

## 10. Поиск без тупика

**Зачем:** пустой результат сейчас = уход.

**Где:** `script.js` (`renderCatalog`), `index.html`.

**Что сделать**

1. При пустом результате показывать блок:
   - «По запросу «nike» ничего не нашлось»;
   - кнопка «Написать менеджеру» (Telegram, с подставленным текстом запроса через `?text=`);
   - кнопка «Смотреть всё» — сброс фильтров и сортировки;
   - 4 ближайших товара из той же категории, если она выбрана.
2. Добавить подсказки-чипы под пустым состоянием: популярные категории («часы», «наушники», «колонки»).
3. Не показывать пустое состояние, пока каталог грузится.

**Приёмка:** запрос `asdasd` даёт понятный экран с двумя действиями; сброс возвращает каталог; переход в Telegram открывает чат с текстом.

**Оценка:** 2 часа.

## 11. «Вы смотрели»

**Зачем:** возврат к товару, который уже заинтересовал.

**Где:** `script.js` (`pf_recent` уже пишется, `renderRecent` уже есть), `index.html`.

**Что сделать**

1. Проверить, что `renderRecent` выводит блок на главной; если он есть только в профиле — вынести на главную под каталог.
2. Показывать 5 последних, исключая товары, которые уже в корзине.
3. Скрывать блок при пустом списке (без пустой рамки).
4. Карточка — та же, что в каталоге, без новых стилей.

**Приёмка:** после просмотра 3 товаров блок появляется; после добавления в корзину товар из блока исчезает.

**Оценка:** 1–2 часа.

## 12. Скорость и вес страницы

**Зачем:** каждая лишняя секунда на мобильном интернете — минус конверсия.

**Где:** `index.html`, `style.css`, `script.js`, `images/`.

**Что сделать**

1. Проверить фактические размеры: `Get-ChildItem images -Recurse | Measure-Object Length -Sum`. Цель — первый экран ≤ 1,5 МБ.
2. Всем изображениям каталога и карточек: `loading="lazy"`, `decoding="async"`, явные `width`/`height` (или `aspect-ratio` в CSS), чтобы не было скачков вёрстки.
3. Первым экрану и логотипу — `fetchpriority="high"`, остальным — нет.
4. Пережать фото товаров до ширины 900 px и качества 80 (WebP, если все браузеры целевой аудитории поддерживают; иначе JPEG).
5. Вынести критический CSS? **Нет** — GitHub Pages без сборки, выгода меньше риска. Вместо этого убрать неиспользуемые правила после удаления юридического блока.
6. Проверить, что `sw.js` не кеширует лишнее и обновляется (`pf-store-vN`).
7. Прогнать Lighthouse на мобильном профиле: цель — Performance ≥ 85, LCP ≤ 2,5 с.

**Приёмка:** размер первой загрузки уменьшился, макет не «прыгает», офлайн-кеш работает, версия SW обновилась.

**Оценка:** 3–4 часа.
